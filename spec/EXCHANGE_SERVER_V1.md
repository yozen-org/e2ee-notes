# 交換サーバープロトコル v1

デバイス間で保管庫を一度だけ引き継ぐための、ブラインドリレー（中継）サーバーの仕様です。
暗号化済みのペイロードを一時的に預かり、短命な URL で受け渡します。サーバーは内容を
復号できません（ゼロ知識）。

## 概要

- 送信側はペイロード（暗号化済みの保管庫引継ぎデータ）をアップロードし、取得用 URL を受け取る。
- 受信側はその URL を開いてペイロードをダウンロードし、インポートする。
- ペイロードは不透明なバイト列として扱う。サーバーが解釈・復号することはない。
- 取得は一度きり。成功後に削除する。未取得でも TTL を過ぎれば失効する。

## データモデル

- `transfer`: 1 回の引継ぎ。次の要素からなる。
  - `token`: サーバーが生成するランダムな識別子（下記）。
  - `payload`: 不透明なバイト列。暗号化済みの引継ぎデータ。
  - `expiresAt`: 失効時刻。
- `payload` の形式はサーバーの関心事ではない。参照実装では
  `VaultTransfer`（保管庫鍵エンベロープと暗号化オブジェクト群）を JSON で扱うが、
  サーバーはこれを検証・解釈しない。

## トークン

- サーバーが生成する。`CSPRNG` から 32 バイトを取得し、base64url（パディングなし）で
  符号化したもの（43 文字）。
- トークンが、その `transfer` を取得できる唯一の能力（capability）である。
- 推測困難性はトークンのエントロピー（256 bit）のみに依存する。

## エンドポイント

共通: 通信は HTTPS。リクエスト／レスポンスの本文は JSON（ペイロード本体を除く）。

### `POST /v1/transfers`

ペイロードを登録し、取得用 URL を返す。

- リクエスト本文: ペイロード本体（`Content-Type: application/octet-stream` を推奨。
  参照実装では `application/json` も受け付ける）。
- レスポンス: `201 Created`

```json
{
  "url": "https://<host>/v1/transfers/<token>",
  "expiresAt": "2026-09-30T12:00:00Z"
}
```

### `GET /v1/transfers/{token}`

ペイロードを取得する。取得成功後、その `transfer` は削除される。

- レスポンス: `200 OK`（本文は登録時のペイロード本体、登録時の `Content-Type`）。
- `404 Not Found`: トークンが存在しない・失効済み・取得済みのいずれか。

## TTL

- 既定は 15 分。サーバー運用者が設定できる。
- 失効時刻は登録時にサーバーが決める。クライアントから短縮を要求してもよい（任意）。

## 制限

- ペイロードの最大サイズ（参照実装の既定は 1 MiB）。超過は `413 Payload Too Large`。
- レート制限はサーバー運用者の裁量。仕様では必須としない。

## エラー

- エラーは `{ "error": "<code>" }` の JSON を返す。
  - `404 not_found` / `413 payload_too_large` など。

## セキュリティモデル

- ゼロ知識: サーバーが保持するのは `token`・`payload`（暗号文）・`expiresAt` のみ。
- 能力モデル: `token` を知る者のみが取得できる。URL の共有経路（QR など）の保護は
  クライアントの責務。
- 一度きり: 取得と同時に削除するため、再取得や第三者による後からの取得を防ぐ。
- TTL: 未取得の転送を時間経過で失効させる。

## 参照実装

Cloudflare Workers + KV による参照実装を `exchange-server/` に置く。仕様は言語非依存であり、
このエンドポイントを満たす任意の実装（Go など）と相互運用できる。

## クライアントの流れ

1. 送信側: 保管庫をエクスポート → `POST /v1/transfers` → URL を QR／リンクで表示。
2. 受信側: URL を開く（QR スキャン）→ `GET /v1/transfers/{token}` → ペイロードを取得 → インポート。
