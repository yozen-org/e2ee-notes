# 交換サーバープロトコル v1（永続 BlobStore）

暗号化されたオブジェクト（操作ログ）を端末間で継続同期するための、ゼロ知識の
永続オブジェクトストレージの仕様です。サーバーはキーと値を不透明なバイト列として
扱い、内容を解釈・復号しません。

## 概要

- クライアントは任意の「オブジェクトキー」でバイト列を保存・取得する。
- オブジェクトは不変（同一キーには同じ内容）。追記型の操作ログに適合する。
- 永続保存。TTL や一回きり削除はない。端末がオンラインになった時に同期できる。
- ゼロ知識: サーバーはオブジェクトのキーと値を読み取らない。

## データモデル

- `object`: 「オブジェクトキー」（文字列）と「値」（不透明なバイト列）の組。
- オブジェクトキーはクライアントが決める任意の文字列（パス区切り `/` を含んでよい）。
- 名前空間（どの利用者のデータか）はクライアントの責務。参照実装では vault 鍵から
  一方向に導出した値をキーの接頭辞に使う。サーバーは構造を解釈しない。

## エンドポイント

共通: HTTPS。オブジェクト本体は raw bytes（`application/octet-stream`）。

### `PUT /v1/objects/{key}`

オブジェクトを保存する。`{key}` は URL エンコードされたオブジェクトキー。

- リクエスト本文: 値（raw bytes）。
- レスポンス: `201 Created`。既に同じキーが存在する場合は内容を上書きせず `200 OK`。

### `GET /v1/objects/{key}`

オブジェクトを取得する。

- レスポンス: `200 OK`（本文は raw bytes）。存在しない場合は `404 Not Found`。

### `GET /v1/objects?prefix={prefix}`

指定した接頭辞を持つオブジェクトキーの一覧を返す。

- レスポンス: `200 OK`。JSON の文字列配列（キーの一覧）。

```json
["room.json", "rooms/abc/operations/def.json"]
```

### `DELETE /v1/objects/{key}`

オブジェクトを削除する（トゥームストーン回収などに使う）。

- レスポンス: `204 No Content`。存在しない場合は `404 Not Found`。

## 制限

- 値の最大サイズ（参照実装の既定は 1 MiB）。超過は `413 Payload Too Large`。
- 一覧はページングしてもよい（`limit` / `cursor`）。参照実装では既定の上限で返す。

## エラー

- エラーは `{ "error": "<code>" }` の JSON を返す。
  - `404 not_found` / `413 payload_too_large` など。

## セキュリティモデル

- ゼロ知識: サーバーが保持するのはキー・値（暗号文）のみ。
- 能力モデル: オブジェクトキーの接頭辞（namespace）を知る者のみが一覧・取得できる。
  namespace はクライアントが vault 鍵から一方向に導出し、QR ペアリングで共有される。
- 鍵（vault 鍵）はサーバーを経由せず、端末間の QR で直接交換する。

## 参照実装

Cloudflare Workers + KV による参照実装を `exchange-server/` に置く。仕様は言語非依存であり、
このエンドポイントを満たす任意の実装（Go など）と相互運用できる。

## クライアントの流れ

1. 鍵交換（QR）: 受信側が公開鍵を表示 → 送信側が vault 鍵をラップ → エンベロープを返す
   → 受信側が accept。これで両端末が同じ vault 鍵を持つ。
2. 同期: 各端末が操作ログを BlobStore へ push/pull する。端末がオンラインの時に
   追記型の操作をマージし、射影し直す。
